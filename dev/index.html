HTSLib.jl

HTSLib.jl calls htslib, the C library behind bgzip, tabix and samtools, in-process, from Julia. It loads htslib from htslib_jll, so there is nothing to install besides the package.

Its main use is as a reference implementation: a way to ask htslib what it makes of a file, and to compare a Julia package's answers, or its speed, with htslib's, without starting a process for each call. So it reports what htslib does, as htslib does it: its positions, its parsing, its corrections and its messages.

What it covers

  • BGZF: compressing and decompressing files, as bgzip does.
  • Tabix: building TBI and CSI indexes, with htslib's presets or columns of your own, as tabix does, and reading the records of an indexed file, by region or from start to end.
  • SAM, BAM and CRAM: reading alignments and their headers, by region with an index, or from start to end, as samtools view does.
  • Records: records that own their bytes, or views of htslib's buffers that read a file without allocating.
  • Low-level bindings: HTSLib.Bindings, a ccall of each C function the package uses, and others that packages need, with htslib's structs and constants.

A tabix record is a line with htslib's interval: the package doesn't parse its other columns, whatever the format, BED, GFF, VCF or another. It doesn't read BCF files, write alignments, or read FASTA files, except as htslib does for CRAM references. The bindings cover more than the package itself, such as writing alignments and building their indexes, which its tests use.

Installation and platforms

using Pkg
Pkg.add("HTSLib")

HTSLib.jl requires Julia 1.12, and uses htslib 1.19.1, the version its bindings are generated from; HTSLib.version() gives the version that's loaded.

htslibjll builds htslib for Linux, macOS and FreeBSD, but not for Windows. On Windows, the package loads, so that packages that depend on it do too, but `HTSLib.isavailable()isfalse`, and every call into htslib fails.

First steps

A BED file, compressed and indexed, then read by region:

using HTSLib
using HTSLib: bgzip, tabix_index, overlaps

directory = mktempdir()
path = joinpath(directory, "features.bed")
write(path, "chr1\t1000\t1500\tfirst\nchr1\t1999\t2100\tsecond\nchr2\t0\t50\tthird\n")

compressed = bgzip(path)
tabix_index(compressed)

TabixFile(compressed) do file
    overlaps(file, "chr1:1001-2000")
end
2-element Vector{TabixRecord{HTSLib.Owned}}:
 TabixRecord("chr1", 1000, 1500, "chr1\t1000\t1500\tfirst")
 TabixRecord("chr1", 1999, 2100, "chr1\t1999\t2100\tsecond")

Each record has its sequence, its interval and its line. The interval is htslib's, 0-based and half-open, whatever the file's own positions are; Positions and intervals describes how each part of the package counts.

The manual

  • BGZF and tabix compresses files, builds and loads indexes, and reads tabix-indexed files.
  • SAM, BAM and CRAM reads alignment files, their headers and their records.
  • Positions and intervals describes 0-based and 1-based positions throughout: in files, in records, in queries, and as htslib corrects them.
  • Records and iteration describes records that own their bytes and views that borrow htslib's, and how to read without allocating.
  • The GenomicFeatures extension gives records the interval interface of GenomicFeatures.
  • Messages and errors describes what htslib reports, and what the package throws.
  • The Reference and Low-level bindings list every documented function and type.

HTSLib.jl exports its types, such as TabixFile and AlignmentRecord, and none of its functions: they're public, imported by name or qualified, since their common names would clash with those of packages loaded alongside, such as GenomicFeatures' each_overlap and htslib_jll's bgzip:

using HTSLib                                  # TabixFile, AlignmentFile, the record types, …
using HTSLib: tabix_index, overlaps, records  # the functions a program calls
HTSLib.pos(record)                            # or qualified
