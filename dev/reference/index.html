HTSLib.HTSLib — Module
HTSLib

Julia bindings to htslib, the C library behind bgzip, tabix and samtools, from htslib_jll.

HTSLib compresses files with BGZF, builds and loads tabix indexes, and reads records by region or from start to end, as the bgzip and tabix command-line tools do. It reads SAM, BAM and CRAM files, from start to end and by region, as samtools does. Its use is as a reference implementation, to validate and benchmark Julia packages against htslib in-process, so it reports what htslib finds rather than offering an API of its own for the formats. The low-level bindings are in HTSLib.Bindings.

HTSLib.AbstractAlignment — Type
AbstractAlignment

An alignment that htslib read: an AlignmentView of a buffer of htslib, or an AlignmentRecord that owns its data.

string(record) is the SAM line of the record, as samtools view prints it, with every field. The accessors take the names of the SAM specification's fields, with aliases where the specification names a field otherwise:

AccessorValueAliases
qnameQNAME, "Query template NAME"template_name
rnameRNAME, "Reference sequence NAME", or nothing without onereference_name
posPOS, "1-based leftmost mapping POSition", or 0 without oneposition
end_positionthe last reference base that the CIGAR covers, 1-based, as htslib's bam_endpos computes it; derived, not a field—
reference_indexthe 1-based index of RNAME into sequence_names, or 0 without one; derived, not a field—

A record overlaps a region from left to right if pos(record) <= right and end_position(record) >= left. With GenomicFeatures loaded, group_name, left_position and right_position give rname, pos and end_position.

HTSLib.AlignmentFile — Type
AlignmentFile(path::AbstractString; index = nothing, reference = nothing)
AlignmentFile(f, path::AbstractString; kwargs...)

An open SAM, BAM or CRAM file, as samtools opens it, with its header.

  • index: the path of the index, BAI, CSI or CRAI, for queries; by default, the index next to the file. The index is loaded at the first query.
  • reference: the path of the FASTA reference of a CRAM file. Without it, htslib looks the reference up as samtools does, through the REF_PATH and REF_CACHE environment variables, which may download it.

As samtools does, htslib adds MD and NM tags computed from the reference to the records of a CRAM file.

Call close when finished, or pass a function f to call with the file, which is closed afterwards.

HTSLib.RecordView — Type
RecordView

A record that htslib read: the 1-based index of its sequence in sequence_names(file), its interval, and its line. Positions are 0-based and half-open, as htslib reports them: start is the position of the first base, and stop the position after the last.

The line is in a buffer of htslib that the next record overwrites, so a view is only valid until the next iteration. String(record) copies the line, and TabixRecord(file, record) copies the whole record.

HTSLib.TabixFile — Type
TabixFile(path::AbstractString; index = nothing, threads = 0)
TabixFile(f, path::AbstractString; kwargs...)

An open file, BGZF-compressed or plain, with its tabix index, as tabix opens it. The index is found next to the file, unless index gives its path. A plain file needs index, such as that of its compressed copy, and can be read from start to end with each_record, but not queried. threads is the number of threads that decompress the file, or none.

Call close when finished, or pass a function f to call with the file, which is closed afterwards.

HTSLib.TabixRecord — Type
TabixRecord

A record that htslib read, with its sequence name, its interval and its line. Positions are 0-based and half-open, as in RecordView.

sequence_name(record) gives its sequence name, from the column that the tabix specification calls col_seq, the "Column for the sequence name". With GenomicFeatures loaded, group_name(record) gives it too, and left_position and right_position give the 1-based, inclusive interval.

HTSLib.bgzip — Function
bgzip(source::AbstractString, destination::AbstractString = source * ".gz"; level = nothing, threads = 0) -> String

Compress the file source into the BGZF file destination with htslib, as bgzip does, and return destination. Unlike bgzip, source is kept.

level is the compression level, from 0 to 9, or htslib's default; threads is the number of threads that compress blocks, or none.

HTSLib.each_overlap — Method
each_overlap(file::AlignmentFile, region::AbstractString)
each_overlap(file::AlignmentFile, sequence::AbstractString, left::Integer, right::Integer)
each_overlap(file::AlignmentFile, sequence::AbstractString, range::AbstractUnitRange)

Iterate over the records of file that overlap a region, as samtools view file region does, yielding an AlignmentView of each. The region is a samtools region string, such as "chr1:1001-2000", "chr1" or "*" for the records without a position, or a sequence name with 1-based, inclusive positions. As in htslib, a sequence that the header does not have has no records.

Queries need the index of the file, and a BAM, CRAM, or SAM file compressed with bgzip. Each view is only valid until the next iteration, and queries of the same file must not interleave.

HTSLib.each_overlap — Method
each_overlap(file::TabixFile, region::AbstractString)
each_overlap(file::TabixFile, sequence::AbstractString, left::Integer, right::Integer)
each_overlap(file::TabixFile, sequence::AbstractString, range::AbstractUnitRange)

Iterate over the records of file that overlap a region, as tabix file region does, yielding a RecordView of each. The file must be BGZF-compressed. The region is a tabix region string, such as "chr1:1001-2000" or "chr1", or a sequence name with 1-based, inclusive positions. As in htslib, a sequence that the index does not have, or a region that htslib cannot parse, has no records.

Each view is only valid until the next iteration, and queries of the same file must not interleave.

HTSLib.each_record — Method
each_record(file::AlignmentFile)

Iterate over every record of file from its start, yielding an AlignmentView of each, as samtools view reads them. The file is opened again, so iterating does not disturb queries. Each view is only valid until the next iteration; copy keeps a record.

HTSLib.each_record — Method
each_record(file::TabixFile)

Iterate over every record of file from its start, yielding a RecordView of each, as htslib reads them with tbx_readrec. Header lines, the first line_skip lines and those that start with the meta character of the index, are skipped, as when the index was built.

The file is opened again, so iterating does not disturb queries. Each view is only valid until the next iteration.

HTSLib.tabix_index — Method
tabix_index(path::AbstractString; preset = :bed, kwargs...) -> String

Build an index of the BGZF-compressed, sorted file path with htslib, as tabix does, and return the path of the index.

  • preset: the columns of the file, as tabix -p: :gff, :bed, :psltbl, :sam or :vcf.
  • sequence_column, begin_column, end_column: 1-based columns that replace those of the preset, as tabix -s, -b and -e.
  • zero_based: whether positions are 0-based and half-open, as tabix -0, instead of 1-based and inclusive; by default, as the preset says.
  • meta_char: the character that starts header and comment lines, as tabix -c.
  • line_skip: the number of lines to skip at the start of the file, as tabix -S.
  • csi: build a CSI index, path * ".csi", as tabix -C, instead of a TBI index, path * ".tbi".
  • min_shift: the bins of a CSI index at the finest level are 2^min_shift bases, as tabix -m; 14 by default.
  • index: the path of the index, instead of the default.
  • threads: the number of threads that decompress the file, or none.
